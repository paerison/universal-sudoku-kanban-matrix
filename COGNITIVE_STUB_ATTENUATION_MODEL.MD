## 4. Tuning and Calibrating the Stub

An incorrectly configured stub can degrade system health. If a tuning stub is left completely open without a terminal short or time boundary, it acts as an infinite delay line, dropping the user into unfocused hyper-fixation spirals or distraction rabbit holes. Tuning the cognitive stub requires the manipulation of three structural variables:

### 4.1 Stub Positioning (Proximity to the Operational Load)
The Creative Pause cannot be applied as a post-collapse recovery tool *after* total executive burnout has already occurred. It must be positioned right before the execution boundary. The activation toggle must trigger the moment the system registers an organizational block or verification bottleneck.

### 4.2 Stub Length (Temporal and Volumetric Boundaries)
The Sandbox state must be explicitly bounded to remain a resonant tuning tool. This is achieved by implementing strict time-boxes (e.g., 20-minute ideation blocks) or card capacity limits within the sandbox zone. This ensures that the wave remains focused and returns to the main execution line after a calculated interval.

### 4.3 Grounding and Collapse (Shifting from Open to Shorted Stubs)
When the creative sprint concludes, the stub shifts from an **Open State** (free-form exploration) to a **Shorted State** (systemic grounding). The user triggers the "Unpause" command, which re-engages the matrix checking loop. The system runs an automated reflow calculation, allowing the user to systematically anchor those newly iterated ideas back into valid, non-conflicting slots on the primary execution matrix.
